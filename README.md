# reqdep — 需求依赖管理库

单项目的需求依赖（阻塞）关系管理，数据保存在进程内存中，由 SprintReq 上层直接调用，无接口层。

## 概念

- 需求使用唯一标识（`string`），通过 `Load` 一次性载入，之后不增删。
- `A 阻塞 B` 表示 B 依赖 A，库内有向边为 `A -> B`。
- 影响查询沿阻塞方向返回全部直接及间接受阻需求，每项只出现一次，不包含起点。

## API

```go
m := reqdep.NewManager()

// 1. 载入需求及初始依赖（初始依赖须无环，否则返回 error）
err := m.Load(
    []string{"A", "B", "C"},
    [][2]string{{"A", "B"}, {"B", "C"}}, // A 阻塞 B，B 阻塞 C
)

// 2. 提交一批依赖调整（建立 OpAdd / 解除 OpRemove）
//    仅当全部调整应用后的最终关系图无环时整批生效并返回 true；
//    出现任何环（含自环）则整批拒绝，状态完全不变并返回 false。
//    判定只看最终图，不因中间状态有环而拒绝最终合法的批次。
ok := m.Commit([]reqdep.Op{
    {Type: reqdep.OpRemove, Blocker: "B", Blocked: "C"},
    {Type: reqdep.OpAdd, Blocker: "C", Blocked: "A"},
})

// 3. 查询下游影响：返回被 C 阻塞的全部直接及间接需求
//    每次调用返回独立切片，后续调整不会改写已返回的结果。
blocked := m.BlockedBy("C") // => ["A", "B"]（顺序不定）
```

## 语义约定

- 同一关系在一批内只出现一次；调用方保证建立的关系原先不存在、解除的关系原先存在。
- 一项需求可通过多条路径阻塞同一需求；只有最后一条可达路径被解除，目标才从查询结果中消失。
- 拒绝的批次不产生任何副作用：原有依赖与所有影响查询结果完全不变。

## 测试

```sh
go test ./... -v
```
